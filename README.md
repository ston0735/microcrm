# 精冠智能 GAME CRM + Pipeline + PMS + AI 助理

可運作的單一團隊 CRM，支援本機 SQLite 與 Vercel PostgreSQL。繁體中文、深色側欄、白色卡片、紫色主題與右側助理。正式版（版本號與更新紀錄見網站左下角）；新增功能、驗收與限制見 V1-RELEASE.md／V1-ACCEPTANCE.md。雲端安裝見 CLOUD.md。

## 快速啟動

本機模式需要 **Node.js 24**（內建 `node:sqlite` 與 FTS5），啟動本機模式無需 npm install，Windows／macOS／Linux 可使用同一份程式。雲端模式另依賴 pg 套件，由部署程序安裝。

1. 將整個 `game-crm` 資料夾放在可讀寫的本機磁碟。
2. 在該資料夾開啟終端機。
3. 複製 `.env.example` 為 `.env`，首次啟動可先使用示例設定。
4. 執行：

```sh
node --env-file-if-exists=.env local-server.mjs
```

開啟 <http://127.0.0.1:3210>。支援 npm 的環境亦可使用 `npm start`。

若出現無法開啟 SQLite，確認 `DATA_DIR` 為可寫入的本機目錄，勿使用唯讀、網路磁碟或不支援檔案鎖定的目錄。啟動程序會建立資料庫與附件目錄。

## 示例登入

| 角色 | 帳號 | 密碼 |
| --- | --- | --- |
| 管理員 | admin@game.local | GameDemo!2026 |
| 協作成員 | sales@game.local | SalesDemo!2026 |
| 唯讀 | viewer@game.local | ViewDemo!2026 |

全部客戶、姓名、商機、專案與金額皆為虛構示例，無真實財務意義。資料只在新資料庫首次啟動時建立，不會每次重新啟動覆蓋修改。

管理員可在「設定與審計」新增帳號、調整其他帳號角色。使用者可修改自己的密碼。管理員／成員共用同一團隊資料；此版**沒有部門、個人客戶隔離或多租戶**。

## 可操作功能

- Dashboard：未結案商機數、商機預估金額、專案數、任務與跟進摘要；不將預估值當實際營收。
- 公司與多位聯絡人：公司詳情可新增聯絡人並查看關聯商機、專案、拜訪、會議與附件。新增商機時也可直接新增公司與聯絡人，查詢台灣公開公司資料後確認帶入。
- 六階段商機：新商機 → 需求洽談 → 方案提案 → 報價議價 → 待簽約 → 結案。最後階段以「成交／未成交」區分；未成交須填原因。
- 成交轉專案：成交商機詳情按「成交轉專案」。同一商機重複操作會回傳既有專案，並自動套用產品六個里程碑。原商機保持關聯；已轉專案的商機不能改成未成交。
- 六階段專案：啟動規劃 → 需求確認 → 設計製作 → 開發整合 → 測試驗收 → 交付維運。看板支援拖移與下拉選單切換階段。
- 四產品範本：GAME 系統、虛擬展間、PMS 專案管理、客製化網站／軟體。範本見設定頁；專案詳情可編輯每個里程碑的狀態、內容與日期。範本目前由程式設定，沒有範本管理畫面。
- 跨商機與專案任務看板：待辦、進行中、待確認、已完成；負責人、截止日、優先級、內容與關聯。
- 拜訪與跟進：日期、方式、與會人、討論、需求、競品、意向、預算、下一步、跟進時間。附件由詳情的「新增檔案」連結至拜訪。
- 會議紀錄：逐字稿、摘要、決議、變更、風險、待辦與附件。可按「建立會議待辦草稿」，檢視內容後確認建立任務。
- 檔案：本機上傳／下載、公司與各紀錄關聯，單份上限 5 MB。TXT／MD／CSV／JSON／LOG 會擷取 UTF-8 內文；PDF／Office／圖片目前僅搜尋名稱與說明，沒有 OCR 或全文解析。
- 搜尋：SQLite FTS5 trigram；少於 3 字以 LIKE 補足繁體中文短字查詢，最多 100 筆結果。按上方搜尋輸入後 Enter。
- AI 聊天與草稿：個人聊天歷史、工具查詢、提出任務與階段更新草稿、確認／拒絕、審計。

## AI 模式與 API 設定

**未設定金鑰**：明確顯示「演示模式／規則式資料查詢，並非真實 AI」。依關鍵字取資料；找不到時展示目前商機／專案清單，沒有自然語言推理、摘要生成或假裝模型。可用「建立寫入草稿」選擇資料，完整演示確認工作流。其餘 CRM 功能不依賴金鑰。

設定 `.env`：

```dotenv
OPENAI_API_KEY=你的金鑰
OPENAI_MODEL=gpt-4.1-mini
```

重新啟動後進入 API 模式。使用原生 fetch 呼叫 OpenAI Responses API，工具為 `search_records`、`get_record`、`propose_task`、`propose_stage`。模型可改為你的帳號有權限使用、支援 Responses 工具呼叫的模型。**本次交付未使用真實 API 金鑰驗證**，API 權限、配額及模型可用性需在你的環境驗收。

模型會取得本次對話、使用者名單，以及工具查詢回傳的資料；公司紀錄、逐字稿或附件文字可能傳送至 OpenAI。採 `store:false`，但不代表本地應用可決定供應商所有資料保留政策。請先確認公司允許此資料處理方式。金鑰只存在伺服器環境，不回傳瀏覽器，不納入版控。

官方工具呼叫說明：<https://developers.openai.com/api/docs/guides/function-calling>

### 寫入保護

1. AI 工具只能建立草稿，無直接修改工具。
2. 草稿限定建立者處理；唯讀角色不能建立或確認。
3. UI 展示目標、前後階段、任務內容與負責人。
4. 使用者明確按確認後，以交易執行，重新檢查欄位、關聯與權限。
5. 更新階段需匹配原紀錄版本，過期草稿不能覆蓋新修改。
6. 草稿確認與資料寫入同一交易；重複確認回傳 409，拒絕不修改業務資料。
7. 草稿建立、確認／拒絕與資料前後值寫入 audit。

模型建議仍需人工檢查；任意文件內容不視為授權指令。

## 部署與保存資料

### 乾淨本機／自有伺服器

建立新的 `.env`，**在第一次啟動前**設定：

```dotenv
SEED_DEMO=0
ADMIN_EMAIL=你自己的管理員Email
ADMIN_PASSWORD=至少12字元的唯一強密碼
DATA_DIR=./data
HOST=127.0.0.1
PORT=3210
```

僅建立管理員，不建立任何示例公司或示例帳號。改 `.env` 不會重設現有帳號密碼，也不會移除既有示例資料；現有示例資料庫需使用新 `DATA_DIR` 才能乾淨啟動。

預設僅監聽本機。若使用自有伺服器，維持此設定並在前方放 HTTPS 反向代理，設定 `COOKIE_SECURE=1`，代理保留原 Host。需要給內網使用時可改 HOST，但須自行設定網路存取限制。單一 Node 程序啟動，不要使用多實例共用網路磁碟上的 SQLite。

此環境驗證時使用系統暫存目錄保存預覽資料，因工具管理的工作目錄不允許 SQLite 正常建檔。正式部署請使用自己的可寫入磁碟；暫存預覽不是正式備份。交付源碼不包含該預覽資料庫。

### 備份與還原

1. 先正常停止 Node 服務。
2. 備份完整 `DATA_DIR`（`crm.sqlite`、可能存在的 WAL／SHM 與 `uploads/`），不要僅複製附件或僅複製 DB。
3. 還原到可寫入目錄，將 DATA_DIR 指向該目錄再啟動。
4. `.env`（尤其 API 金鑰）另行安全保存。

目前沒有內建定時備份、異地備份、加密儲存或恢復 UI。管理員刪除會留下審計內容，但沒有資源垃圾桶／還原功能；附件刪除後須由備份恢復。

### GitHub 與 Vercel

原始碼可放入 **GitHub 私有儲存庫**；不要提交 `.env`、`data/`、真實附件或資料庫。`.gitignore` 已排除這些資料。

本機版使用 SQLite；新增雲端版使用 PostgreSQL 與 Vercel Functions。部署步驟、環境變數、檔案上傳及限制請參閱 [CLOUD.md](CLOUD.md)。雲端版尚未完成實際資料庫與 Vercel 端到端驗證，不能將 README 的部署成功視為 CRM 已上線。

## 測試與驗收

```sh
node --test tests/*.test.mjs
```

測試各自建立臨時資料庫，不會修改你的正式資料。測試需要本機 TCP 權限，`http.test.mjs` 會啟動並關閉獨立隨機 port 的伺服器。`domain.test.mjs` 驗證外鍵、成交轉專案、六里程碑、重複轉換、驗證、版本衝突、搜尋、草稿確認／拒絕與審計，也以模擬 Responses 回覆驗證工具呼叫只建立草稿及服務錯誤處理；`http.test.mjs` 驗證 HTTP 登入、CSRF、來源限制、角色、CRUD、手動建立專案的六個里程碑、附件全文搜尋／下載、聊天保存與登出。先前本機版 3 項測試曾全部通過。新增雲端測試後共 5 項；本次 4 項業務邏輯測試通過，HTTP 測試因執行環境拒絕本機 TCP 連線（EACCES）無法完成；模擬 API 測試不等於真實 API 連線驗證。

人工驗收：

1. 以管理員登入，新增公司與兩位聯絡人，重整確認保存。
2. 新增商機，填需求、金額與下一步；移到結案時選成交。
3. 商機詳情轉專案，檢查六個里程碑；再轉一次確認沒有重複。
4. 新增拜訪、跟進時間與會議逐字稿，從詳情關聯附件。
5. 上傳 TXT 後搜尋一段內文，確認能找到；下載驗證內容。
6. 助理建立任務草稿，先確認任務未出現，再確認執行；檢查看板及審計。
7. 建立階段草稿後從看板修改同筆資料，再確認草稿，應被版本衝突阻止。
8. 用 viewer 登入，確認沒有寫入按鈕，直接呼叫寫入 API 也會被拒絕。
9. 設定 API 金鑰後，詢問「查詢 GAME 商機，依已記錄風險建議下一步，先提出任務草稿」。檢查來源、草稿與確認流程；API 連線為本次未完成的驗證。

## 維護與擴充

- `domain.mjs`：階段、產品、範本、欄位白名單、伺服器端驗證。
- `db.mjs`：SQLite schema、關聯、資料 repository、交易、seed、審計。
- `assistant.mjs`：全文搜尋、AI 工具、草稿確認、演示模式。
- `local-server.mjs`：HTTP、Cookie session、CSRF、角色、附件、靜態檔。
- `public/`：介面與互動，不使用編譯工具。
- `tests/`：可重複執行的領域與 API 測試。

資料模型以各 entity 表 + JSON payload 保存擴充欄位，關聯另建實體 FK 欄位。metadata（ID、版本、時間）由伺服器管理。下一版應增加正式 migration 機制、分層路由與 repository 介面，再遷移至 ORM／PostgreSQL；新增 relation 欄位時必須同時 migration，不要僅改欄位白名單。

基本安全已做密碼 scrypt、HttpOnly SameSite session、CSRF、8 小時 session、登入失敗限流、版本控制、檔案下載需登入、SQL 參數化、內容跳脫和角色限制。這些是 MVP 基礎，沒有完成外部安全稽核。
